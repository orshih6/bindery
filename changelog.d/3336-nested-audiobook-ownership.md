### Fixed
- **Deleting a book no longer removes files that belong to a book nested inside its folder** (#3336). Reported by foobarbigtime. An audiobook tracked as a whole folder, such as a box set with a subfolder per volume, can contain a folder that another book tracks as its own. Deleting a book with its files, deleting one of its files, or the cleanup after a reassign used to protect only a file another book tracked by its exact path, so files in that nested folder could be removed. Bindery now skips any file that sits under a folder another book tracks, leaves it on disk, and logs it. Deleting a whole book then succeeds but leaves those files behind. Deleting a single file under another book's folder is refused with a message saying so, and removing it without deleting from disk still works.
